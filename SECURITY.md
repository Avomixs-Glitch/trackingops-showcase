# TrackingOps Security Policy

Security reports are taken seriously. Because TrackingOps is private-source software and this repository is public, vulnerability details must not be disclosed through a public issue, discussion, pull request, or screenshot.

## Reporting a vulnerability

Contact the repository owner through a private channel and include only the information required to begin triage:

- the affected TrackingOps version;
- the affected surface (desktop, installer, product website, API, or integration);
- a concise description of the impact;
- reproducible steps or a minimal proof of concept;
- relevant logs or screenshots with credentials, tokens, user identities, hostnames, and customer data removed.

If no private contact channel is available, request one from the [repository owner](https://github.com/Avomixs-Glitch) without including vulnerability details in the public message.

## Scope and safe research

- Test only systems and accounts that you own or are explicitly authorized to assess.
- Do not access, modify, retain, or disclose another person’s data.
- Do not perform denial-of-service, destructive, persistence, social-engineering, or supply-chain attacks.
- Stop testing if you encounter credentials, secrets, personal information, or customer data.
- Give the team a reasonable opportunity to investigate before any coordinated disclosure.

## Supported versions

TrackingOps is currently distributed through controlled channels. Security fixes are delivered for the latest available preview or release build unless the TrackingOps team communicates otherwise.

## Public repository

This repository contains product presentation material, not the application source. Reports about the README, public imagery, broken links, or non-sensitive presentation issues may be opened publicly. Product security findings must remain private.
